Features

The ASUS bits Omarchy doesn't cover yet.

Omarchy already handles brightness, audio and power. Vivobook Control adds the hardware that's specific to this laptop, and remembers every setting across reboots, suspend and shell restarts.

Keyboard RGB

Any color, plus Static, Breathe, Rainbow or the firmware's own effect. It drives the ITE5570 controller directly, which asusctl doesn't support.

Keyboard light

A 4-step backlight slider that stays in sync with the Fn keys. Right-click or scroll the bar icon to change it without opening the panel.

Performance

Quiet, Balanced or Performance, with live CPU temperature. It's the only control that changes how the fan behaves on this model.

Battery charge limit

Cap charging at 60, 80 or 100 % to keep your battery healthy when you're mostly plugged in. The limit is restored at boot and after resume.

Copilot key, reclaimed

Omarchy maps it to the menu. Make it launch your default Omarchy agent, toggle this panel, or run any command. Changes need no reload.

Gestures & edge slides

Hyprland multi-finger gestures, plus the ASUS edge sliders for brightness, volume and back/forward. Taps, scrolling and palm rejection work exactly as before.

Built for Omarchy

Feels like part of Omarchy, because it uses Omarchy.

It isn't a separate app or tray icon. Vivobook Control is an omarchy-shell plugin that calls Omarchy's own commands, so it picks up your theme, your agent and your power settings.

omarchy-shell · bar widget

Your bar, your theme

Built from the shell's own components and theme colors, so it changes with every theme you switch to. Try the buttons above.

omarchy-menu → Hardware

In the Omarchy menu

Vivobook Control, Keyboard RGB Next Color and Touchpad Edge Gestures are added next to Omarchy's own hardware entries.

omarchy-osd

The OSD you already know

Keyboard light, color and profile changes show the Omarchy OSD. Edge slides go through omarchy-brightness-display and omarchy-audio-output-volume.

omarchy-powerprofiles-set

Respects your power settings

Profiles are set through Omarchy, so its separate AC and battery memory and its battery-aware switching keep working.

omarchy-agent --pick

Copilot key → your agent

By default the Copilot key opens your default Omarchy agent in a terminal, or the agent picker if you haven't set one.

omarchy plugin add · update · remove

Managed by Omarchy

Install, update and remove it with Omarchy's own plugin manager, like any other shell plugin.

~/.local/state/omarchy/toggles/hypr/vivobook.lua

Your Hyprland config stays yours

Keybindings and gestures are written to the toggles folder that Omarchy loads on every hyprctl reload. Nothing under ~/.config/hypr is touched, so Omarchy updates and your own edits never conflict.

Keyboard RGB

Match your keyboard to your theme.

The swatches are the Tokyo Night palette Omarchy ships with, and any hex color works from the CLI. The Vivobook S 14 keyboard is a single RGB zone behind an ITE5570 controller, which asusctl doesn't support, so Vivobook Control talks to it directly.

  • Any hex color with vivobook-ctl rgb set
  • Animated effects run by a tiny user daemon that survives suspend
  • Next color from the Omarchy menu or a keybinding
Touchpad

Gestures made for Hyprland workspaces.

Toggle each one in the panel. The 3-finger swipe uses Hyprland's live workspace animation, and edge slides bring back the ASUS Windows sliders.

3-finger swipe ↔

Switch workspace with a live swipe animation.

4-finger swipe ↔

Carry the focused window to the next workspace.

Pinch

Toggle floating for the focused window.

Edge slides

Right edge brightness, left edge volume, top edge back/forward.

Command line

Scriptable, like the rest of Omarchy.

Every control is also a vivobook-ctl command and an omarchy-shell IPC call, ready for your own Hyprland bindings.

  • JSON status for your own widgets and scripts
  • Shell IPC: omarchy-shell vivobook rgbNext
  • doctor shows what's unlocked and how to fix the rest
❯ vivobook-ctl rgb set 7aa2f7
❯ vivobook-ctl rgb effect breathing
❯ vivobook-ctl profile set performance
❯ vivobook-ctl charge set 80
❯ vivobook-ctl copilot set agent-pick
❯ vivobook-ctl status --json # all panel state
❯ vivobook-ctl doctor        # what's unlocked
❯ omarchy-shell vivobook profileCycle
Security

Powerful, without running as root.

Nothing runs as root at runtime. One setup step grants exactly the access the plugin needs, and nothing more.

01 · Verified setup

Root never installs from your home folder

setup.sh copies its files into a root-owned staging folder, checks them against SHA256SUMS (and your own --expect digest), and only then installs from that copy.

02 · Least privilege

Access goes to your seat, not a group

The RGB controller, uinput and touchpad are opened to the logged-in user through udev uaccess ACLs. No group changes, no re-login.

03 · Narrow sudo

One helper, three values

The only sudoers entry allows a tiny charge-limit helper that accepts 60, 80 or 100 and nothing else. A root-owned uninstaller removes it all.

Install

Two commands on any Omarchy install.

Omarchy's plugin manager adds the panel to your bar. A one-time sudo step then unlocks RGB, the charge limit and edge slides. It shows the payload digest before installing anything.

1omarchy plugin add https://github.com/leandrooricchio/omarchy-vivobook.git --enable
2sudo ~/.config/omarchy/plugins/io.github.leandrooricchio.vivobook/setup.sh

To update, run omarchy plugin update, then run setup.sh again; vivobook-ctl doctor tells you when it's needed. To remove everything, run sudo /usr/local/libexec/vivobook/uninstall, then omarchy plugin remove.
